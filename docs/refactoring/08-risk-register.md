# Risk Register

| Risk | Rating | Evidence / required mitigation |
|---|---|---|
| Entity/schema provisioning/templates | `CRITICAL` | `setup-schemas/lib/{schema,drumate}.js`; lock fresh/existing behavior and result shapes |
| Factory warm pool | `CRITICAL` | CLI consumes `drumate_create`/`desk_create_hub`; identify daemon, states and recovery |
| MFS deletion/import/export | `CRITICAL` | CLI DB stores touch shards and disk; test isolation and partial failure |
| Mixed schema ownership | `CRITICAL` | Task/channel data under `schemas/common`; module-aware templates/migrations |
| Split plugin discovery/lifecycle | `HIGH` | REST loader, UI bootstrap and Debian installer use separate contracts |
| Runtime globals | `HIGH` | UI-core/UI-team window globals and server shared global caches |
| Window Manager/Finder/DnD | `CRITICAL` | `ui-team/builtins/media/core.js` and window seed graph |
| ACL engine/policy ownership confusion | `CRITICAL` | ACL JSON drives dispatch, but service policy is not generic engine behavior; fixture every scope/permission and preserve module ownership |
| CLI direct DB/shard access | `CRITICAL` | Raw yp queries and qualified calls; stable API requires parity |
| CLI DB/API difference | `CRITICAL` | API backend throws; parity absent |
| Procedure result leakage | `HIGH` | `setup-schemas/lib/drumate.js::createHub` documents mixed result sets |
| Webpack aliases/dynamic imports | `HIGH` | UI seed registry and environment-driven signin build |
| Team boot sequence | `CRITICAL` | bootstrap events/globals span ui-core and ui-team |
| Mistaking UI Team for the minimal shell | `CRITICAL` | UI Team boot files also register the integrated Team application; derive the host contract through tests before selecting symbols |
| Provisioner/runtime/CLI semantic cycle | `HIGH` | All mutate yp, shards and storage |
| Patch/upgrade order | `CRITICAL` | schema patch trees and Debian schemas-patch |
| Docker/native divergence | `HIGH` | two deployment channels require shared scenarios |
| Repo-layout packaging | `HIGH` | Debian build matrix names Team repos |
| Existing installs/version skew | `CRITICAL` | consumer ranges differ from imported package versions; define matrix |
| Plugin integrity/rollback | `HIGH` | Debian script shallow clones/copies/deletes without transaction |
| Missing automated baseline coverage | `CRITICAL` | server-team/CLI/signin lack package tests |
| Apparent duplicates/deprecated code | `MEDIUM` | Usage not proven; retain and investigate |
| Reference package identity collisions | `CRITICAL` | Marketplace identifies as `@drumee/loby`; loby/marketplace point to analytics-server; descriptor identity cannot inherit package metadata blindly |
| Legacy onboarding migration | `CRITICAL` | Loby supersedes onboarding-server, but their divergent same-named schemas require an explicit deployed-data migration/upgrade path |
| Hidden host contracts in frontend examples | `HIGH` | Signin and sandbox-ui consume global LETC/router/session objects without compatibility declarations |
| Sandbox public provisioning/destruction | `CRITICAL` | `sandbox.json` exposes create/remove to anyone/public-api and service code mutates domains, users, hubs and disk |
| Marketplace callback/security boundary | `CRITICAL` | Anonymous ACL endpoints rely on JWT/HMAC and MFS permission checks in service code; preserve service-specific policy |
| Marketplace unregistered payment code | `HIGH` | `service/lib/payment.js` lacks mapped ACL, schema and Stripe dependency; do not treat it as live behavior without runtime evidence |
| Static onboarding accidentally reintroduced | `LOW` | Source is retained only by baseline immutability; target distributions must not package it |
| ACL catalogs without implementation mapping | `HIGH` | Phase 1 found `acl/{block,menu,ops,wicket,ws}.json` without `modules`; characterization freezes the set, but live reachability is unresolved (`tests/compatibility/acl/catalog.test.js`) |
| ACL service without source permission | `HIGH` | Phase 1 found `desk.set_online_status` lacks `permission.src`; live authorization behavior must be recorded before dispatcher changes |
| Secure-share public implementation ambiguity | `CRITICAL` | `acl/secure_share.json` declares an empty public module path; its anonymous/current routing and policy behavior require live characterization |
| Search-projection transaction boundary blocks baseline provisioning | `CRITICAL` | The authoritative `sources/debian/tests/e2e-local.sh` run built images but `schemas-populate` exited 1. `sources/server-team/offline/factory/schema.js::create_entity` calls `publish_search_projection`, while `sources/schemas/common/procedures/mfs/mfs_search_projection_rebuild.sql` explicitly signals `SEARCH_PROJECTION_REBUILD_ACTIVE_TRANSACTION`. Pool rows then remain unusable and `sources/setup-schemas/lib/organization.js::createSystemUser` fails after `EMPTY_FACTORY`. Preserve the evidence; establish the supported transaction/runtime combination before schema, MFS, or provisioning refactoring. |
| Mandatory live baseline coverage remains blocked | `CRITICAL` | Safe characterization passes and the authoritative Docker E2E was executed, but the populate defect prevents REST golden capture and live provisioning/MFS/CLI/browser scenarios. `scripts/test-env/gate.sh` correctly reports `FAIL` for Debian E2E and `SKIP` for every unconfigured mandatory surface. This remains blocking for Team/self-hosting parity claims and for refactoring that depends on the unresolved provisioning/MFS path. It does **not** block the isolated no-Team Phase 2 runtime extraction or the `hello` kernel slice, provided that work does not depend on the uncharacterized provisioning path. |
| Copying Team policy into `server-runtime` | `CRITICAL` | Generic candidates in `sources/server-team/router/rest/index.js::{getModule,run}` are co-located with secure-share ceilings, over-limit clamps and service lists. Extract only descriptor resolution, lazy worker loading and generic authorization; keep policy with its service/distribution. |
| Recreating `server-core` as `server-runtime` | `CRITICAL` | `sources/server-core/lib/**` mixes session/ACL with entity, Hub, user and MFS concerns. Require symbol-level necessity for boot, context, authorization, dispatch or module hosting before accepting a runtime dependency. |
| Recreating `ui-core` as `ui-runtime` | `CRITICAL` | `sources/ui-core/letc/index.js` initializes core context beside `DrumeeMFS`; Team boot adds further application behavior. Prove every first-runtime symbol through the `hello` host rather than copying its current neighbors. |
| MFS/application builtin kinds leak into the first frontend runtime | `CRITICAL` | `sources/ui-core/letc` co-locates static kinds and MFS/media-related registrations. Inventory the minimum generic LETC set; defer `DrumeeMFS`, media kinds, Finder and associations until post-`hello` MFS work. |
| Host/Visitor/Organization semantics drift from ACL expectations | `CRITICAL` | `sources/ui-core/letc/index.js` creates all three global contexts used by host applications. Treat them as kernel-level context candidates and characterize their client/server identity relationship before extraction. |
| `Kind.loadPlugin` / `bootstrap.plugin` handshake breaks | `CRITICAL` | `sources/ui-core/letc/kind/index.js::{loadPlugin,registerAddons}` and `sources/server-team/service/bootstrap.js::plugin` rely on `{ path }`, dynamic bundle load and `addons:registered`. Add an exact `hello` vertical-slice test before changing discovery. |
| Premature universal module descriptor | `HIGH` | Current backend ACL discovery uses `acl/*.json`; frontend discovery uses `index.json`. Do not merge or replace either contract before `hello` proves both; version association remains `INVESTIGATE`. |
| Team compatibility treated as the first-kernel design constraint | `CRITICAL` | Team includes MFS, Finder, Window Manager, collaboration and policy surface that a new module host does not need. Use Phase 1 as evidence and selected regression reference, not as a requirement to copy all Team behavior before `hello`. |
| Window Manager enters before MFS/resource model is understood | `HIGH` | Window/DnD behavior in `sources/ui-team/src/drumee/modules/desk/wm/**` is coupled to Team/browser/MFS assumptions. Defer it until after intentional MFS primitives and an explicit resource-host decision. |
| Marketing-specific behavior promoted into the kernel | `HIGH` | Marketing may need hubs, schemas, AI and policy, but its workflows are not generic proof. Classify each new requirement against Essentials, runtime, system module and marketing module before implementation. |
| Historical/current `server-essentials` semantic skew | `CRITICAL` | Baseline locks resolve `1.3.1`, while the imported current source is `1.3.6`. In particular, `lex/{permission,privilege}.js` assigns different numeric values to `write`; `get` is absent from the current tables and the generic converter returns zero for it. `server-team/router/rest/index.js::Acl.getModule` converts ACL strings with `permissionValue`. Phase 2 now has focused current-semantics descriptor/ACL tests; any temporary legacy mapping belongs in `server-runtime`, never Essentials. This does not block isolated no-Team extraction, but it blocks untested Team ACL-parity claims. |
| Phase 2 generated-route host wrapper drifts from setup-infra | `CRITICAL` | The live Phase 2 test uses the pinned `setup-infra` generator and includes its generated `routes/app.conf` verbatim; the small surrounding Nginx server block only supplies a disposable listener and temp paths. Keep service/plugin route assertions and `nginx -t`; do not replace the generated route set with an independent proxy configuration. |
| Disposable generator writes host-owned state | `HIGH` | The first live run showed Docker root ownership can make `.tmp/test-env/kernel` non-removable. The final wrapper runs generator/Nginx as the invoking UID, confines all mounts to the guarded root and root-cleans only the known generated directory. Preserve these ownership/path tests. |
| Kernel validated behind an invented/simplified HTTP contract | `CRITICAL` | The pinned infrastructure source defines `/-/` routing in `sources/setup-infra/templates/etc/drumee/infrastructure/routes/app.conf.tpl`: `/(svc|vdo|service)/` proxies to `restPort`, while `/-/{app,api,plugins}/` use aliases. Phase 2 must generate and validate this contract with `setup-infra`, then exercise a service and plugin/static route through Nginx rather than substitute a hand-written proxy. |
| Historical Debian Team image used as the new-kernel host | `CRITICAL` | `sources/debian/scripts/build-images-local.sh` builds `server-pod` from `server-team` and UI images from `ui-team`; injecting a runtime into those images would make Team a hidden dependency. The clean-Debian kernel integration image must be a separate disposable test artifact; historical containers remain baseline/self-hosting/Team-compatibility evidence only. |
| `setup-infra` mutable or unpinned during kernel tests | `HIGH` | `sources/setup-infra` is now pinned in `SOURCE_MANIFEST.md` at `643d74fa8bc89d418ff1169daa09554ae84e48ef`. Test tooling must consume that source directly, never clone a moving GitHub branch at build or run time. |
| Unrelated host services leak from `setup-infra` into kernel scope | `HIGH` | `sources/setup-infra/infra.js` also renders BIND, Postfix/DKIM, MariaDB and PM2 configuration; `jitsi.js` covers Jitsi/Prosody/Coturn. Phase 2 may derive only its Nginx/HTTP contract and must not turn DNS, mail, Jitsi or other host services into runtime dependencies. |
| Kernel config generation mutates host `/etc` | `CRITICAL` | `sources/setup-infra/templates/index.js::chroot` supports `--chroot`/`--outdir`, but `sources/setup-infra/infra.js::writeInfraConf` also creates runtime/cache paths. Run the generator inside a disposable container or with all resolved roots under `.tmp/test-env/kernel/`; assert no production `/etc` change. |
| Schemas or MFS pulled forward only to satisfy initial ACL | `CRITICAL` | Phase 3 `hello` is approved to use `permission: { src: anonymous, fast_check: public-api }`, avoiding database ACL procedures. Preserve that boundary: no `acl_check.sql`, `user_permission`, `user_expiry`, MFS schemas or factory provisioning may enter Phase 2 solely to execute generic dispatch. Add database-backed ACL only when an authenticated/resource-aware capability proves its need. |
| Skeleton API exposes unresolved kinds | `CRITICAL` | Corrective Phase 2.6 inventories all 27 unique public paths in `sources/ui-core/letc/toolkit/skeletons.js`: 23 non-MFS builders are registered before READY and four have final documented exclusions (`Messenger` Team; `Profile`, `UserProfile`, `Progress` MFS). `tests/ui-runtime.test.js` invokes every retained builder and asserts a real Marionette Widget lineage. Do not expose future paths without the same closure proof. |
| Static Kind catalog is incomplete before plugin loading | `CRITICAL` | `target/foundation/ui-runtime/src/bootstrap.js` registers all 12 retained static kinds before publishing `READY`; `KindRegistry.loadPlugin()` awaits that promise, and the retained-catalog test exercises all 23 builders. Keep registration and gating coupled. |
| Legacy kind namespace leaks into kernel code | `HIGH` | `sources/ui-core/letc/index.js` creates the historical namespace and several skeleton builders dereference it. Phase 2.6 adapts retained builder paths to literal historical strings and has a source/static plus browser test with `window.KIND` absent. A later Team adapter, if justified, must stay outside the kernel. |
| Plugin races bootstrap | `CRITICAL` | Historical `Kind.loadPlugin()` may observe globals initialized by the `drumee:bootstraping` sequence. The new `KindRegistry` waits on the single runtime `ready` promise even for already static kinds; a deferred-bootstrap test proves a request cannot resolve early. |
| Singleton initializes more than once | `HIGH` | `sources/ui-core/letc/{index,host,user,organization}.js` rely on process/browser singletons. Phase 2.6 uses a per-browser-global `WeakMap` and tests that duplicate `bootstrap()` calls return one environment and emit one bootstrap event. |
| Synthetic renderer mistaken for LETC evidence | `CRITICAL` | Corrective Phase 2.6 replaces the callable descriptor renderer with actual Backbone/Marionette View and CollectionView ancestry adapted from `ui-core`. Chrome now asserts a mounted `Skeletons.Note` Widget is a Marionette View and separately renders the normal `ui-dev-tools/widget` class/skeleton/skin pattern. Preserve both checks. |
| Elementary Widget pulls MFS or Team | `CRITICAL` | The retained real closure includes box/text/SVG/list/entry/file-selector/image-smart/menu/rich-text behaviour only after source-level reductions. The unit scan rejects Team/MFS imports; profile/progress remain MFS-deferred and Messenger is Team-deferred. Any new retained method requires a dependency-closure review, especially if it touches radios, service policy or storage. |
| SCSS alias imports historical product coupling | `HIGH` | Historical widget skins use `@use 'mixins/drumee'` and old shortcut aliases. The retained Phase 2.6 skin uses no aliases; Webpack builds a real style-importing Widget fixture with the shared `ui-build` rules. Do not add legacy aliases as hidden kernel defaults. |
| Host/Visitor/Organization retain hidden MFS dependency | `HIGH` | Historical user/organization classes subscribe to media radios, routing and bootstrap state. `target/foundation/ui-runtime/src/context.js` retains only data and identity methods; unit tests cover the reduction. Auth/MFS behavior is deferred to an approved later capability. |
| ui-essentials ownership remains ambiguous | `HIGH` | Corrective inspection confirms no ui-runtime production import of `@drumee/ui-essentials`, so the dependency is intentionally absent. `src/validator.js` is a precisely documented CJS adaptation of `ui-essentials/utils/validator.js`, not a replacement Essentials package. A later direct consumer must add and test the pinned dependency explicitly. |
| Browser test bypasses actual Widget rendering | `CRITICAL` | `tests/integration/kernel/ui-runtime-browser.test.js` compiles `src/browser.js` via `ui-build`, opens it in Chrome, calls `Skeletons.Note`, and mounts the resulting class. It also compiles the canonical developer Widget fixture. Do not replace these with direct DOM fixture assertions. |
| Generic runtime primitive remains stranded in Team | `HIGH` | Corrective review inspected `sources/ui-team/src/drumee/builtins/messenger/index.js`; it is conclusively Team chat/attachment/MFS behaviour, so no Team primitive was extracted. Repository placement must continue to be treated as evidence rather than ownership: extract a generic Team-originated primitive only with a precise provenance record and runtime-independence test. |
| Placeholder bootstrap global hides missing semantics | `HIGH` | `Preset`, `Template`, Validator, Contexts and pointerDragged now have implemented values; Websocket is absent rather than published as historical `null`, because no retained non-MFS consumer requires it. Do not reintroduce empty objects or null services to satisfy name parity. |
